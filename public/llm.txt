# sintfoap.xyz — Drift for AI agents (llm.txt)

Drift is a personal organiser on sintfoap.xyz. This site runs an MCP server
that lets you, an AI agent, do everything the person who gave you a key can do
in Drift: read and change their collections and items, share collections with
other Drift users, and add store plugins. You act as that person.

## Connect

- MCP endpoint: https://sintfoap.xyz/mcp   (Streamable HTTP, POST only, JSON replies)
- Auth: header `Authorization: Bearer sf_...` (an API key)
- Claude Code example:
    claude mcp add --transport http drift https://sintfoap.xyz/mcp --header "Authorization: Bearer sf_..."
- Other clients: add a remote/HTTP MCP server with that URL and header.

Requests that carry an `Origin` header (browsers) are refused, and cookies are
ignored. GET and DELETE on /mcp return 405. Refusals (401 bad or missing key,
403 account not allowed, 405, 413 body over 64 KB) are JSON-RPC error bodies.
After making a key the account page shows a ready-to-run `claude mcp add` command.

## Getting a key (the person does this)

1. Sign in at https://sintfoap.xyz and open Account settings (/account).
2. In "API keys", name the key, enter the password, press "Make a key".
3. Copy the key now; it is shown once. Give it to the agent.
4. To cut the agent off, press Revoke on the same page.

A key has full Drift access as its owner. Treat it like a password. Changing
the password or signing out everywhere does NOT revoke keys; revoke them on
the account page. A key stops working if the account is disabled, loses Drift
access, or is deleted.

## Data model

- Collection: a named list of items, id `c_` + 10 hex digits (name up to 100
  characters; up to 100 collections). Each has `plugins` (which plugins are on),
  an optional `view` (plugin shown first), and `order`. A new account has one
  collection, "Inbox". You can't delete your last collection.
- Item: id `i_` + 10 hex digits. Fields: `title` (required, up to 500),
  `notes` (up to 20000), `tags` (lowercase, no #, up to 50), `collection`, and
  `meta`. Up to 5000 items per owner.
- `meta` holds one slice per plugin, keyed by plugin id. Built-in plugins:
    checklist  {done: boolean, priority: 0-3}                      a task to tick off
    event      {start, end}  "YYYY-MM-DD" (all day) or "YYYY-MM-DDTHH:MM"; end may be null
    list       {order: number, parent: item id | null}              an outline
    graph      {links: [item ids], rel?: {item id: type}, kind?}  links to other items;
               a typed link ("leads to", "depends on" …) points from this item to the other
    location   {place, lat, lng}  where it happens. Send {"place": "1 Ferry
               Building, San Francisco"} and the site finds it (lat, lng and the
               name it found), or {"lat": 37.7955, "lng": -122.3937} and it
               names the spot. A place it can't find is refused.
    weather    {outdoor: boolean}  an outdoor item: Drift warns when the forecast
               for its day looks wet (rain at least 50% likely, 2 mm or more, or
               thunderstorms). The forecast is at its place, else its
               collection's base, else near the person.
  Set a slice to null in an update to take the item off that plugin. A
  plugin's data only shows if the plugin is on for the item's collection.
- A collection with Locations can have `bases`: where each day's route starts
  and ends. [{place, lat, lng, from, to}] with from/to as YYYY-MM-DD for the
  days it covers (from = to for one day), or both left out for the home base.
  A day's base is the one covering it most closely. A day's route keeps timed
  events in time order, visits linked items one after the other (in the
  link's direction when it has a type), and orders the rest by shortest travel.
- Deleting is soft: send `deleted: false` in an update to restore.
- Sharing: the owner shares a collection with another Drift user by username,
  role `edit` (add and change items) or `view` (read only). Shared collections
  appear in your state with your `role`. Items can only move between
  collections with the same owner.
- Ids shown in drift_get_state are the only ids to use. Call it first. (For a big account, read it
  a collection at a time with include_notes false, then fetch notes only where you need them.)

## Tools

- drift_get_state                 {collection?, include_notes?, limit?, cursor?}  Collections (with shares and your role),
                                  items, plugins, store plugins. Collections and plugins are always complete; items come
                                  in pages of 200 (limit up to 500). When the result has `next_cursor`, call again with
                                  it as `cursor` for the next page; `total_items` is the count. Pass `collection` for
                                  one collection's items, `include_notes: false` to leave notes out. `version` changes
                                  whenever the person's data does, so check it if items may have changed between pages.
- drift_get_agenda {day}          Events due or late on `day` (YYYY-MM-DD).
- drift_get_item {id}             One item, including a deleted one.
- drift_create_item               {title, collection, notes?, tags?, meta?}
- drift_update_item               {id, title?, notes?, tags?, collection?, meta?, deleted?}  Only sent fields change; each meta slice is replaced whole.
- drift_delete_item               {id}
- drift_create_items {items}      Up to 50 drift_create_item argument objects in one call.
- drift_update_items {items}      Up to 50 drift_update_item argument objects ({id, ...}) in one call.
                                  Both do each in turn; one that fails doesn't stop the rest. The result is
                                  {done, failed, results: [{index, item} | {index, error}]}, index being its place in your list.
- drift_link_items                {from, to, type?, remove?}  Link two items in Graph. No type: a plain two-way link.
                                  A type ("leads to", "depends on", "blocks", "part of", or your own) points from -> to.
                                  remove: true removes any link between them. Routes visit linked places one after the other.
- drift_create_collection         {name, plugins?, view?}
- drift_update_collection         {id, name?, plugins?, view?, order?, deleted?}  Owner only.
- drift_delete_collection         {id}  Owner only.
- drift_share_collection          {id, username, role?: "edit" | "view"}  Owner only; sending again changes the role.
- drift_unshare_collection        {id, username}  The owner removes anyone; a guest can remove themselves.
- drift_set_bases                 {id, bases}  Replace a collection's bases (anyone who can edit it).
- drift_plan_route                {collection, day, profile?, option?}  The day's best orders from its base and back,
                                  with travel times; profile driving-car | foot-walking | cycling-regular.
- drift_get_map                   {collection, day, profile?, option?, width?, height?}  A PNG picture of the day's Map:
                                  OpenStreetMap streets, the route, the base (a house) and the stops as numbered pins in
                                  visiting order (1-9, then A-Z; red = likely late). Comes with a text block listing the
                                  stops by label, the travel time and distance. 800x600 by default (320-1280 wide, 240-1280 high).
- drift_find_place                {query, near?} -> {results: [{place, lat, lng}]}, or {lat, lng} -> {place}.
                                  Check what an address finds before putting it in meta.location. Needs the site's
                                  OpenRouteService key; without it, give locations as {lat, lng}.
- drift_install_plugin            {id}  Add an approved store plugin (ids in drift_get_state's `store`).
- drift_uninstall_plugin          {id}

Results are JSON in a text block (drift_get_map: an image block, then the JSON). Mistakes (bad field, not found, view-only,
limits) come back with `isError: true` and a plain message; fix and retry.
Not-found is also what you get for another person's ids.

## Examples

Add a high-priority task:
  drift_create_item {"title":"Pay rent","collection":"c_...","meta":{"checklist":{"done":false,"priority":3}}}

Schedule an event:
  drift_create_item {"title":"Dentist","collection":"c_...","meta":{"event":{"start":"2026-03-05T14:30","end":"2026-03-05T15:15"}}}

Give an event a place (the collection needs the location plugin on to show it):
  drift_update_item {"id":"i_...","meta":{"location":{"place":"Ferry Building, San Francisco"}}}

Tick a task off:
  drift_update_item {"id":"i_...","meta":{"checklist":{"done":true,"priority":3}}}

Nest an item under another in a list:
  drift_update_item {"id":"i_child...","meta":{"list":{"order":1,"parent":"i_parent..."}}}

Add a few stops for a day and see the route:
  drift_create_items {"items":[{"title":"Coffee","collection":"c_...","meta":{"event":{"start":"2026-03-05T09:00"},"location":{"place":"Blue Bottle, Oakland"}}},
                               {"title":"Museum","collection":"c_...","meta":{"event":{"start":"2026-03-05"},"location":{"place":"SFMOMA"}}}]}
  drift_link_items {"from":"i_coffee...","to":"i_museum...","type":"leads to"}
  drift_get_map {"collection":"c_...","day":"2026-03-05"}

Share a collection read-only:
  drift_share_collection {"id":"c_...","username":"josh","role":"view"}

## Not available

Chat, Recipe box, notifications, and writing or reviewing store plugins are
not part of this server; neither are accounts, passwords or keys.
